# custom-radius

Самописный RADIUS-сервер на Python для аутентификации Wi-Fi по протоколу
**PEAP-MSCHAPv2** с проверкой учётных данных в Active Directory через
Samba/winbind. Без сторонних RADIUS-фреймворков (FreeRADIUS и т.п.) — весь
протокол (RADIUS, EAP, PEAP/TLS-туннель, MSCHAPv2) реализован вручную на
чистом Python + pyOpenSSL.

## Возможности

- RADIUS Access-Request/Accept/Reject/Challenge с HMAC-MD5
  Message-Authenticator (проверяется всегда, отключить нельзя)
- PEAP-туннель (TLS 1.2) с ручной фрагментацией/сборкой сообщений
- Внутренний EAP: Identity → MSCHAPv2 challenge/response → Result TLV
- Проверка пароля через `ntlm_auth` (Samba winbind), с опциональной
  проверкой членства в AD-группе
- Генерация MPPE-ключей (MS-MPPE-Recv/Send-Key) для WPA-Enterprise
- Многопоточная обработка запросов: медленный ответ контроллера домена
  не блокирует аутентификацию остальных пользователей
- Поддержка нескольких сетей/IP точек доступа (`RADIUS_CLIENT_IP` принимает
  список через запятую, включая CIDR: `192.0.2.0/24,198.51.100.5`)
- Единая нормализация логина независимо от формата (`user`,
  `user@domain`, `DOMAIN\user`) — с корректной обработкой MSCHAPv2
  challenge-hash по RFC 2759
- Read-only веб-панель мониторинга (`admin_web.py`) без сторонних
  зависимостей: статус службы, таблица попыток входа (кто прошёл / кого
  отклонили), безопасное редактирование части конфигурации

## Установка

Зависимости:

```bash
pip install pyOpenSSL
```

Сервер аутентифицирует пользователей через `ntlm_auth`, поэтому машина
должна быть присоединена к домену через Samba/winbind (см.
`smb-radius.conf`, `krb5-radius.conf`). Проверить:

```bash
wbinfo -t
wbinfo -u
```

## Конфигурация

Скопируйте шаблон и заполните реальными значениями:

```bash
sudo mkdir -p /etc/custom-radius
sudo cp .env.example /etc/custom-radius/radius.env
sudo chmod 600 /etc/custom-radius/radius.env
```

По умолчанию оба скрипта читают `/etc/custom-radius/radius.env`. Другой
путь задаётся переменной `RADIUS_ENV` (сервер) или первым аргументом
командной строки (веб-панель).

Все ключи из `.env.example` реально читаются кодом — параметров-пустышек
в шаблоне нет. Ключевые:

- `RADIUS_SHARED_SECRET` — общий ключ с точкой доступа/контроллером
- `RADIUS_LISTEN_IP` — интерфейс, на котором слушает сервер (не `127.0.0.1`,
  если запросы идут от реальной точки доступа по сети)
- `RADIUS_CLIENT_IP` — кто может слать запросы: `*`, один IP, или список
  через запятую с поддержкой CIDR (`192.0.2.10,198.51.100.0/24`)
- `RADIUS_TLS_CERT_FILE` / `RADIUS_TLS_KEY_FILE` — сертификат и ключ для
  PEAP-туннеля. Если сертификат от публичного CA (Let's Encrypt, Sectigo и
  т.п.) — **обязательно включите в `RADIUS_TLS_CERT_FILE` полную цепочку**
  (лист + промежуточные), иначе многие клиенты (особенно iOS) не смогут
  проверить сертификат
- `RADIUS_SERVER_NAME` — имя, которое клиент сверяет с CN/SAN сертификата.
  **Должно быть DNS-именем**: iOS не умеет сопоставлять IP-адрес со списком
  `TLSTrustedServerNames`. Резолвиться в DNS оно не обязано — суппликант
  только сравнивает строки
- `AD_ALLOWED_GROUP` — группа AD, которой разрешён доступ (`-` — разрешить
  всем успешно аутентифицированным)
- `RADIUS_WORKER_THREADS` — сколько запросов обрабатывается параллельно.
  Каждый может провисеть в `ntlm_auth` до `RADIUS_REQUEST_TIMEOUT_SECONDS`,
  так что это запас на одновременно «медленные» аутентификации

TLS-версия туннеля жёстко зафиксирована на 1.2 и не настраивается: PEAPv0
выводит MPPE-ключи из PRF TLS 1.2, а для TLS 1.3 стандартной привязки
PEAPv0 не существует.

## Запуск

Напрямую (для теста):

```bash
RADIUS_ENV=/path/to/radius.env python3 custom_radius.py
```

Через systemd (продакшен):

```bash
sudo mkdir -p /opt/custom-radius
sudo cp custom_radius.py admin_web.py /opt/custom-radius/
sudo useradd --system --no-create-home custom-radius
sudo usermod -aG winbindd_priv custom-radius
sudo cp custom-radius.service custom-radius-admin.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now custom-radius custom-radius-admin
```

Юниты запускаются с `ProtectHome=true`, поэтому сертификаты и ключ должны
лежать вне `/home` — например в `/etc/custom-radius/`.

## Тесты

```bash
python3 -m unittest -v test_radius
```

Тесты самодостаточны: генерируют собственный временный сертификат, никуда
не ходят по сети и не требуют Active Directory. Покрыты векторы RFC 2759
(при их поломке AD начинает отвергать правильные пароли), фрейминг и
подпись RADIUS-пакетов, шифрование MPPE-ключей, разбор журнала панелью и
порядок старта фазы 2 PEAP.

## Веб-панель мониторинга

`admin_web.py` — дашборд на стандартной библиотеке Python (без
Flask/сторонних пакетов), с HTTP Basic Auth:

```
http://<RADIUS_ADMIN_WEB_LISTEN_IP>:<RADIUS_ADMIN_WEB_PORT>/
```

Показывает:
- статус systemd-службы
- таблицу попыток входа (пользователь, время, MAC устройства, accept/reject,
  причина отказа) — распарсено из journalctl, без сырых логов
- таблицу устройств: связка учётная запись + MAC (`Calling-Station-Id` из
  запроса точки доступа), сколько раз вошёл/отклонён, когда последний раз.
  MAC с установленным битом "locally administered" помечается как
  «случайный» — это MAC-рандомизация iOS 14+/Android 10+ по умолчанию для
  каждой сети, а не признак подмены устройства
- безопасную часть конфигурации (без паролей и ключей)

Логин/пароль задаются в конфиге (`RADIUS_ADMIN_WEB_USER`,
`RADIUS_ADMIN_WEB_PASSWORD`) — обязательно смените дефолтные значения.
После 10 неудачных попыток с одного адреса панель отвечает `429` в течение
5 минут. Счётчик ведётся по адресу TCP-соединения, поэтому за обратным
прокси все запросы придут с одного адреса и подбор пароля заблокирует вход
всем — в такой схеме ограничение частоты нужно настраивать на прокси.

Страница `/edit` позволяет менять безопасные параметры
(`RADIUS_CLIENT_IP`, `RADIUS_LISTEN_IP`, тайминги и т.д.), но **не пишет
конфиг сама** — генерирует готовые команды для ручного применения. Это
осознанное ограничение: процесс панели не имеет прав ни на запись в
защищённый `radius.env`, ни на перезапуск службы без участия
администратора. Команды дописывают параметр, если его ещё нет в файле, —
иначе `sed` молча ничего бы не сделал.

## Тестирование без реальной точки доступа

```bash
eapol_test -c eapol-test.conf -a <IP сервера> -p 1812 -s <shared secret>
```

`eapol-test.conf` в репозиторий не попадает (в нём пароль тестового
пользователя в открытом виде) — создайте свой на основе:

```
network={
    ssid="ваш-SSID"
    key_mgmt=WPA-EAP
    eap=PEAP
    identity="test-user"
    anonymous_identity="anonymous"
    password="пароль"
    ca_cert="/etc/ssl/certs/ca-certificates.crt"
    phase2="auth=MSCHAPV2"
}
```

## Профиль для iOS

Нужен **только если сервер отдаёт сертификат собственного (не публичного)
CA**. При сертификате от публичного CA iOS доверяет ему сам, и профиль не
требуется вообще.

Установка отдельного CA-сертификата на iPhone требует ручного включения
доверия в настройках — это неудобно и часто забывается.
`gen_ios_profile.py` собирает единый `.mobileconfig` с CA-сертификатом и
настройками Wi-Fi, который доверяет этому CA только для указанной сети:

```bash
python3 gen_ios_profile.py --env /etc/custom-radius/radius.env "SSID-сети"
```

SSID берётся из `WIFI_SSID`, если не передан аргументом. Имена для
`TLSTrustedServerNames` берутся из `RADIUS_SERVER_NAME` (можно перечислить
несколько через запятую); IP-адреса из списка отбрасываются с
предупреждением, потому что iOS их не сопоставляет.

## Совместимость с клиентами

PEAPv0 оставляет ряд деталей на усмотрение реализации, и клиенты
расходятся в трактовке. Учтено в коде:

- **Старт фазы 2.** Флайт TLS `ChangeCipherSpec`+`Finished` отправляется
  отдельным EAP-сообщением, а туннелированный `EAP-Identity` — только
  после пустого PEAP-ACK от клиента. iOS отбрасывает прикладные данные,
  пришедшие в одном сообщении с `Finished`, и ждёт фазу 2; Android такой
  «прицеп» переваривает. Если прицепить Identity к `Finished`, iOS зависает
  до таймаута, а Android аутентифицируется — из-за чего проблема выглядит
  как поломка iOS, а не сервера.
- **Заголовки внутреннего EAP.** Принимаются оба варианта — и с 4-байтным
  EAP-заголовком, и без него (PEAPv0 header compression).
- **Формат логина.** `user`, `user@realm` и `DOMAIN\user` сводятся к одной
  учётной записи, при этом challenge-hash считается ровно по той строке,
  которую использовал клиент.

## Безопасность

- Конфиг, приватные ключи (`*.key`) и каталог `certs/` исключены из
  репозитория через `.gitignore` — никогда не коммитьте их
- Message-Authenticator проверяется до обращения к кэшу дубликатов, чтобы
  наблюдатель трафика не мог переигрыванием вытягивать ответы сервера
- Веб-панель никогда не показывает пароли, `RADIUS_SHARED_SECRET` или
  содержимое приватных ключей; пароли не пишутся в журнал ни на одном
  уровне логирования
- Рекомендуется держать `RADIUS_ADMIN_WEB_LISTEN_IP=127.0.0.1` и открывать
  доступ к панели только через SSH-туннель, если не установлен HTTPS
  перед ней
